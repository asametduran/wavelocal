# Wavelocal Roadmap

Living plan for the autonomous evolution loop (`loop.ps1`) in **HYPERCODE mode**: the loop runs continuously,
one headless Claude Code session after another, and only pauses when the Claude Pro quota is exhausted.

## Rules for every run
- Pick the **first unchecked milestone** in the HYPERCODE packs below (A, then B, C, D, E, then any later pack). Fall back to the Backlog only if every pack milestone is blocked.
- A milestone is a **deep engineering deliverable**: multi-file, production quality, with tests where a test runner exists. No 10-line tweaks. If a milestone finishes early and pushed cleanly, continue with the next one in the same session.
- **Verify before every push:** `npm run build` must exit 0, and once they exist `npm run typecheck` and `npm test` must pass. CI (`.github/workflows/build-apk.yml`) runs `npm ci && npm run build && npx cap sync android`, so keep that path working.
- **Commit and push to `origin/main` after every verified milestone** (conventional message, `git pull --rebase origin main` first). Pushing triggers the Android APK build.
- Stay local-first and privacy-first: no analytics, no accounts, no network calls for user audio. Never commit user audio or large binaries; tests generate synthetic audio.
- Keep the web bundle lean: native/desktop code lives under `desktop/` and must not be imported by `src/`.
- If a milestone is blocked: revert partial work, record the blocker under that item, tick nothing, and move to the next milestone.
- Update this file when done (tick the box, add one Changelog line, add follow-ups).

### Pack E - Library depth and production hardening
Written after the deep audit of 2026-10-16 (code review plus a run of the production build with synthetic libraries).
Verified findings that shaped the pack:
- **Search ignores diacritics and Turkish casing**: typing `istanbul` does not find `İstanbul` (`'İ'.toLowerCase()` is two code points), `yarisi` does not find `Yarısı`, `beyonce` does not find `Beyoncé`. Matching is one substring test over `title artist album`, so `beatles help` finds nothing either.
- **Durations are blank for every track that was never loaded**: import stores `duration: 0` and the value learned on first play is not persisted, so the library column, album totals and any duration sort are empty until each song has been played.
- **Import is unbounded and opaque**: `Promise.all` starts a tag read for every file at once (5,000 files = 5,000 simultaneous readers), nothing is committed until all finish, there is no progress count and no cancel.
- **Metadata is thin**: only title / artist / album / cover / lyrics / ReplayGain. No track or disc number, year, genre or album artist, no sort order other than import order, and no way to browse by album or artist (parking-lot item).
- **`window.prompt` is not implemented by Electron**, so "New playlist..." and "Save EQ preset" cannot work in the desktop app; the native `confirm`/`prompt` boxes are also unthemed and outside the focus-trap/axe coverage of every other dialog.
- **Service worker**: precaches only the shell, so lazy chunks and the decode worker are cached after first use (first *offline* use of Sound tools fails if it was never opened online); the cache never evicts old hashed assets (unbounded growth); `skipWaiting` swaps the worker under a running page with no update prompt; e2e blocks service workers, so none of it is tested.
- **No Content-Security-Policy** on the web/PWA/Android build (only the Electron shell has one), and Android `allowBackup="true"` lets the OS copy the WebView's IndexedDB (the whole library) into cloud backups, against the privacy-first promise.
- **No storage visibility**: no usage/quota/persistence readout; a full disk surfaces only as a generic notice. Audio is copied into IndexedDB, so the library costs its size again.
- **Test gaps**: `usePlayer` (1,133 lines) and `engine` (792 lines) are covered only by e2e, there is no coverage tooling or threshold, and the untrusted-input parsers (ID3 rewriter, LRC, backup, share codes, WAV/FLAC) have no fuzz tests. Small performance debts: the track-id `join` runs on every render (the player renders ~4x/s) and hydration does an O(n^2) `includes`.
- Not buildable or testable on this machine (no Java/Android SDK), so recorded here and not scheduled: an Android foreground service with a native media notification for background playback.

- E2: added browsing, sorting and a better search: a forgiving tokenized search (accents, case and the Turkish dotted/dotless i do not matter, every word in any order, `artist:` `album:` `year:` (ranges, decades) `genre:` `folder:`, phrases and `-exclusions`, with a tips panel whose examples add themselves) shared by the track list, albums, artists and folders; a sort menu (title, artist, album, track number, length, date added, play count, year; "A to Z" / "newest first" wording, unknown values last, remembered, next/previous follow it, dragging only in the stored order); Albums and Artists tabs (windowed grid and list, covers and totals, compilations under Various Artists, one Unknown album, arrow-key grid navigation, locate-playing) over whatever list is on screen, and album and artist pages (disc headings, an artist's albums oldest first, Play, Shuffle and Add to playlist for the whole page, links between album and artist) whose Back is the browser's and a phone's Back; playing from a page keeps playing from it while you browse on (`playFrom`, separate from the list on screen); a wider panel on tablets and desktops and root-font-scaled rows for TV; the Folder-view toggle became the Folders tab; the new views are a 6.7 kB lazy chunk (initial JS 123.8 of 125 kB); 235 new unit tests (a mutation run over the pure modules found and closed three gaps) and 58 new e2e tests (search, sorting, albums, artists, keyboard, a 300-album library, phone, tablet and TV layouts, axe), and the racy smart-list e2e tests now wait for the import.
- E3: replaced every `window.prompt`/`confirm` with in-app dialogs and toasts (the dialog and toast views are a lazy chunk; the page behind a dialog is inert, a destructive question starts on Cancel, and Escape, a click outside, a remote's Back key and a phone's Back button all cancel it, the last two through a history-entry layer that leaves a sheet under the dialog open and has to be the first `popstate` listener, because Chromium runs window listeners in the order they were added whatever their phase), which also fixes the desktop shell (Electron has no `prompt`; 6 new Electron smoke tests run the dialogs in the real shell); a `…` menu to rename, duplicate, save as a file and delete a playlist, and an Undo toast plus `Ctrl+Z` for every reversible change (a deleted playlist comes back in its place and is reopened); M3U, M3U8 and PLS import and export (UTF-8, UTF-16 or Windows-1252, `file://` and percent-encoding, Windows and Unix paths; tracks found by path, then by file name with the folders deciding ties, then by another extension, then by a title and artist that fit exactly one track; missing ones listed, internet streams skipped); a real Up Next queue (Play next and Add to queue on track rows and on album and artist pages, an Up Next tab to play, move, remove and clear with Undo) that plays before the list carries on, survives restarts, and is never lost when a queued FLAC is still being decoded at the handover (found in review, pinned by a slowed-decoder e2e test); 166 new unit tests and 52 new e2e tests, with older e2e specs now waiting for saves instead of sleeping; the initial JS is 123.1 of 125 kB because icons that only lazy panels use now travel with their panels.
- E4: made the offline copy reliable and hardened the build. The production build compiles a manifest (size, SHA-256 and content type of every emitted file) into a generated service worker (`sw/sw.ts`, bundled after `vite build` by `scripts/precache.mjs`; the old static `public/sw.js` is gone) that keeps each build in its own versioned cache after checking every byte (a hotel Wi-Fi page answering 200, a truncated or redirected file fails the install and the working copy stays), downloads only the files that changed, deletes older builds and the retired v1 cache but never another app's, opens the app and every lazy panel and the decoder worker with no network, refills its cache if the browser clears it, and waits for a go-ahead before taking over (an in-app prompt, a button in Sound & tools, a second window told; found by the e2e run: a worker that replaces the retired one by itself used to trigger a pointless "update ready" prompt, now it gets a moment to settle first); the desktop and Android apps register no worker, and the Android app removes ones earlier versions left. A build-only Content-Security-Policy meta tag (`default-src 'none'`, no remote host, no inline script, no eval, no unsafe-inline) is checked by `npm run check:dist`, the last step of `npm run build`, which fails if any emitted file type is not one the policy lets a page load, if the page has anything the policy would silently block, or if the offline copy is not whole; Chromium confirms it is enforced and that a realistic session never breaks it. Android: `allowBackup=false` plus Android 12 data-extraction rules, no cleartext and no user certificates, `INTERNET` as the only permission, all pinned by a unit test since the APK cannot be built here. Sound & tools → Storage shows usage against the quota (music, app files, other), warns when room runs low (after an import, once per level), says whether the browser may delete the library and asks it not to, lists the largest tracks with a confirmed Remove, asks before an import that will not fit, and names a full device as the reason when a save fails (and stops reading the rest). Seeded fuzzing of the parsers of untrusted input (lyrics, backup JSON, the ID3 rewriter, M3U/PLS and matching, pairing codes including a decompression bomb, WAV and FLAC, search, and the desktop shell's path and shortcut validators; `FUZZ_RUNS` scales it) found and fixed an `Infinity` lyric timestamp from a huge offset, unbounded lyric size, tags written with text no other player can read back (NUL, a leading byte order mark, half a surrogate pair) and playlist matching that took seconds for a large playlist against thousands of same-named files (now about 75 ms, proven equal to the old rules by a differential test). Coverage (`npm run test:coverage`, V8) has per-area thresholds enforced in CI with a summary and an uploaded report. The tests' time budgets are counted in CPU time, not wall time (a first run on a busy machine failed three of them; the same suites pass with sixteen busy loops competing for twelve cores), and the build accepts file names in any script (it refused anything but ASCII). 417 new unit tests (a mutation run over the new logic caught 32 of 33 changes; the survivor is equivalent) and 26 new e2e tests, with the initial JS at 123.6 of 125 kB.
